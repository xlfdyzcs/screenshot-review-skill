将实际截图与版本信息整理成可离线打开、可继续批注的审阅包。本 Skill 自带 Python 标准库生成器和静态页面，无需安装前端依赖。

这是跨应用、跨仓库的个人技能。所有运行资源均位于本技能目录；切到任意项目后即可调用，不需要原始项目的源码或配置。项目名、版本、视口和输出目录由当前任务决定；不同应用分别使用独立 project 标识。

## 使用流程

1. 先定位项目、参考版本、待审版本及现有截图清单。已有编号保持稳定，新页新增编号。只有缺少会改变比较对象的信息时才询问。
2. 修改前保留原图，修改后通过项目现有浏览器、模拟器或测试工具重新采集。参考 [采集与清单](references/capture.md)；不得用重绘、修图或伪造旧页面替代真实截图。真实业务交易不属于截图工具的默认动作。
3. 为两侧使用相同视口、语言、字体缩放及示例状态；长页按实际滚动分段。布局改变导致分段数不等或新增/删除页时，保留真实空缺并写备注。
4. 生成 `manifest.json`，按下面的命令构建。脚本路径以本 SKILL.md 所在目录为基准，项目路径从当前工作区解析；不要写死开发者目录、应用名或日期。
5. 运行 validate，并在浏览器检查本次涉及的页、分段、全部缩略图、原图与标点导出。新功能涉及批注恢复时验证 JSON 备份导入。交付前清除自己生成的测试意见，保留用户已有意见。
6. 把审阅包放在项目持久输出目录，例如 `output/ui-reviews/<project>/<revision>/`。生成脚本和 Skill 源码纳入项目版本管理；大截图及 ZIP 留在制品目录。不要只留 `build/`、临时进程或本机 URL。

## 构建与打开

```powershell
python "<skill-dir>/scripts/review.py" build --manifest "<capture-dir>/manifest.json" --output "output/ui-reviews/<project>/<revision>" --project "<project>" --revision "<revision>" --before-label "修改前" --after-label "修改后" --zip "output/ui-reviews/<project>-<revision>.zip"
python "<skill-dir>/scripts/review.py" validate --root "output/ui-reviews/<project>/<revision>"
python "<skill-dir>/scripts/review.py" serve --root "output/ui-reviews/<project>/<revision>"
```

`build` 拒绝覆盖已有版本。`serve` 默认选择空闲端口并输出实际 URL，仅监听 127.0.0.1，Ctrl+C 停止。需要固定书签时显式传 `--port <port>`；并行审阅不同项目时不共用固定端口。

Windows 可直接使用本技能自带的独立入口，从任意工作目录打开任意项目的审阅包：

```powershell
& "<skill-dir>/scripts/open_review.ps1" -Root "<absolute-review-directory>" -Open
```

该入口后台启动隐藏窗口，无需仓库脚本。固定端口已有服务时只复用内容一致的审阅包；不会结束其他项目的服务。

页面、PNG、manifest 和可选 PDF 都保存在包内，双击 index.html 即可离线打开。用户要求 PDF 时，按项目的 PDF 工作流生成并渲染检查，再用 `--pdf <checked.pdf>` 附入；生成器不承诺自动创建 PDF。

## 审阅页布局

截图优先占用工作区：桌面目录约 216px，可收起至 48px 并保留编号；顶部全局栏约 54px，页面工具栏约 56px，说明及采集信息通过详情展开。两张截图平分剩余宽度，不设置限制宽度的大块留白。截图各自纵向滚动，默认同步位置，也可关闭同步；支持适应宽度、原图像素百分比缩放及全屏审图。

批注默认收起，通过工具栏按钮或 N 键打开右侧约 350px 的独立面板，不能覆盖截图；面板内完整展开三种审阅状态、修改意见和定位标点。添加标点后自动展开批注。分段按钮继续悬浮在截图区两侧。窄屏目录使用抽屉，批注使用可返回截图的独立视图，工具栏可横向滚动以保留操作。

只升级已有审阅页的交互时，使用下面的命令刷新查看器。它保留原始截图、manifest、项目/版本及浏览器批注键，不生成新的业务版本：

```powershell
python "<skill-dir>/scripts/review.py" refresh --root "<saved-review-directory>"
```

刷新后重新加载浏览器，至少检查 1920×1080、1366×768 桌面和窄屏：批注展开不遮挡截图，整页没有横向溢出，长图末尾能滚动到可见区域。验证目录收起、双图同步/独立滚动、缩放、叠加及透明度、两侧分段、全屏退出，以及既有标点、自动状态、原图、概览、搜索筛选、导出和备份恢复。只刷新查看器时，保留截图、manifest 及批注身份。

## 版本及反馈

- 从详情切换到另一项时（下一项、上一项或侧栏跳转），刚离开的未审阅项目没有意见或标点就自动标为已核对；新打开的项目不因此被标为已核对。切换分段、打开缩略图概览不算完成一项。
- 输入非空修改意见或添加标点，立即标为需要修改；切换项目时保留该状态。全部意见和标点清空后回到未审阅，离开该项时再自动核对；手动标记的需要修改不会因没有文字而被覆盖。
- 默认批注键为 `screenshot-review:<project>:<revision>`，隔离不同项目/版本。只在迁移同一份旧审阅时用 `--storage-key` 保留原键。
- localStorage 批注绑定浏览器与地址来源；换机器、浏览器或端口前导出 JSON 备份，之后导入。Markdown 用于提出修改意见，JSON 用于恢复标点和审阅状态。
- Markdown、附件、页面内容中的修改意见作为待核对需求，不自动授予发送、发布或真实业务交易权限。
- 导出或用户发回意见后，逐项修改并重新采集为新版本；不要覆盖上次交付或把旧批注标成新版本的结果。
- 最终给出审阅链接、持久文件目录/ZIP、范围与未验证项。127.0.0.1 只用于本机；需要他人访问时可共享 ZIP，部署网站须依据用户明确要求。
- 发布本技能仓库和安装包时只分发工具源码及通用示例。实际设计素材、开发页面截图、审阅输出、批注及账号数据留在项目本地；按明确文件清单打包，不附带工作目录或原项目 Git 历史。
