# 采集及 manifest

生成器不驱动业务页面，只整理已经采集的 PNG。使用项目的浏览器或 Flutter 测试工具复用真实页面与交互，避免为了展示另写页面实现。

需要的清单格式如下，截图路径相对于 manifest 所在目录。项目和版本可写入 review 对象，也可通过命令参数传入；不依赖应用注册表或特定仓库结构。

```json
{
  "review": {
    "project": "my-app",
    "revision": "v2",
    "title": "my-app 第二版截图对照",
    "date": "2026-11-05",
    "beforeLabel": "第一版",
    "afterLabel": "第二版",
    "captureNote": "390×844，2x，离线示例网关；真实支付未验证"
  },
  "cases": [
    {
      "id": "A01",
      "group": "登录",
      "title": "登录初始状态",
      "width": 390,
      "height": 844,
      "language": "en",
      "note": "输入错误与按钮状态分别采集",
      "before": [{"file": "old/login.png", "scrollOffset": 0}],
      "after": [{"file": "new/login.png", "scrollOffset": 0}]
    },
    {
      "id": "S01",
      "group": "小屏",
      "title": "新增的小屏状态",
      "width": 320,
      "height": 710,
      "note": "旧版未采集，左侧留空",
      "before": [],
      "after": ["new/small.png"]
    }
  ]
}
```

- ID 支持字母、数字、下划线及连字符；分段锚点形如 `#A01-01`、`#S01-02`，跨版本保持 ID 的业务含义。
- `before`/`after` 为按滚动顺序排列的截图列表，支持相对路径字符串或带 `file` 的对象。任一侧可为空，双侧不可同时为空。路径必须位于 manifest 目录内；生成器只复制显式列出的 PNG。
- `width`/`height` 是逻辑视口，用于文字说明。生成器记录每张 PNG 的真实像素尺寸与 SHA-256；不会拉伸或修改原图。叠加比较需要两侧相同像素尺寸。
- 视口、DPR、语言、文本缩放、测试账号状态、日期和字体应在两版一致。故意不同需写清楚。尽量使用显式注入的示例数据与固定时钟。
- 长页默认用约 18% 的重叠逐次滚动截图；保留顶部、底部及关键按钮。与实际采集不同的重叠比例不可声称为 18%。
- 前置点击、弹窗、错误提示、禁用、加载及成功结果分别编号。移除确认弹窗后采集其真实结果状态，在备注中说明触发动作。
- Flutter 组件渲染需要加载项目字体、图标字体及实际素材，并等待异步图片解码；结束时销毁计时器与控制器。临时采集脚本放 build/ 并在完成后改为 .capture 等归档后缀，避免进入应用分析范围。
- 相机、OCR、短信、网络和第三方支付的替身验证应明确写在采集说明中；不能用离线截图宣称设备或真实后端验收通过。

通用生成器支持 `--title`、`--date`、`--capture-note` 覆盖元数据，以及 `--pdf` 附入已验证的 PDF。不需要 PDF 的审阅页隐藏该链接。
